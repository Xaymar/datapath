Native Rust core of DataPath.

This crate is being built up in phases (see the migration plan): the platform-free parts come first, then the POSIX and Windows backends, then the C ABI and the language bindings. Until the switch-over it lives beside the C++ core and is not published.

  • error: the error codes shared with the C API.
  • proto: the wire format (frame header, handshake, incremental frame parser).
  • queue: the bounded, coalescing, multi-producer send queue.
  • spin: busy-poll for a short budget, then block.
  • options, conn: settings and the platform-neutral connection state machine.
  • api: contexts, sockets and servers, on Linux, Android and macOS so far.

The platform-free modules do no I/O and need no unsafe. The backend under sys is built on rustix and is safe code too, except for three small spots on macOS where rustix has no wrapper (kqueue’s kevent, the quality-of-service call, and sysctlbyname), each a single FFI call.

Modules§

api
The public API: contexts, sockets and servers.
conn
Platform-neutral part of a stream connection: handler storage, framing, the send queue and the close-exactly-once state machine.
error
Error codes. The numeric values are the ones of datapath_error in the C API (datapath.h) and of datapath::error in the C++ API, so they can be passed across the C ABI unchanged.
options
Settings for contexts, sockets and servers. Defaults match the C API.
proto
The wire format: an 8-byte little-endian length followed by the payload, after a 16-byte handshake in each direction. Identical to the C++ core, so a Rust and a C++ peer can talk to each other.
queue
Bounded, coalescing, multi-producer send queue with a single writer slot.
spin
Busy-poll for a short budget, then block.
